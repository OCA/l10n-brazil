DDA inbox for Odoo: the boletos that banks register against the CNPJ of
your company arrive by themselves, each one with its vendor, a suggested
payable title and **one recommended action**, so the usual case is
solved in one click.

This is the backend core. It does not depend on any bank library: a glue
module (for instance one that reads the API of a bank) or a DDA return
file read with ``l10n_br_cnab_structure`` feeds it through
``_dda_upsert``.

What the module does:

- Boleto model (``l10n_br_dda.debit``) with chatter, one record per
  payer CNPJ and digitable line, shared by every source (API connection,
  CNAB file, manual).
- Matching with a score for suggestions and a strict rule for the
  automatic link: same full CNPJ, exact amount, same due date, same
  document number when both sides have one, and a single candidate. Two
  equal installments never link by themselves.
- Assignments (guarantor or registered assignee), root CNPJ, N:1
  installments and tolerance of days and amount are suggestions only.
- Alerts: unknown vendor, no title, possible duplicate, assignment. A
  boleto without title and with an unknown vendor is blocked for payment
  until an approver records the verification.
- Actions with undo: link, create a draft vendor bill, ignore, verify
  and add to a payment order. Nothing edits an invoice: the difference
  of amount goes to the write-off (interest, fine and discount of the
  payment line).
- Bridge to ``l10n_br_account_payment_order``: the digitable line, the
  bar code and the difference travel to the ``account.payment.line``, so
  the CNAB 240 payment file (Segment J) can be generated.
- Import of a DDA return file: the layout is data in
  ``l10n_br_cnab_structure`` (structure marked as DDA return); the demo
  brings a **simulated** one.

Configuration
=============

1. In *Invoicing > Configuration > Settings*, block DDA, choose by
   company:

   - *DDA automatic link* (off by default).
   - *DDA bill creation*: whether a boleto without title recommends a
     draft vendor bill (off by default).
   - The tolerance of days (default 3) and of amount (default zero).
   - The payment mode (CNAB, outbound) of the order that receives the
     boletos and the accounts of the interest, fine and discount.

2. Give the users one of the groups *DDA / User*, *DDA / Approver*
   (releases a suspect boleto) or *DDA / Manager* (policies and
   technical data).
3. A vendor can list *DDA assignees* in the *Invoicing* tab: companies
   that issue boletos in its name.
4. To read a DDA return file, register the layout of the bank as a
   structure of *CNAB Structure* and tick *DDA return*. Each field of
   the detail maps a boleto field in *Content Destination Field*:
   ``digitable_line``, ``beneficiary_vat``, ``beneficiary_name``,
   ``payer_cnpj``, ``date_due`` (DDMMYYYY), ``amount``,
   ``document_number``, ``guarantor_vat``, ``guarantor_name`` and
   ``status_code`` (1 open, 2 paid, 3 cancelled).

Usage
=====

- Open *Invoicing > Vendors > DDA Boletos*. The filters (My queue today,
  Without title, Amount divergence, Suspects, Due in 7 days, Overdue)
  are in the search box.
- Each line shows the recommended action. Select several lines and use
  *Action > Apply recommended actions* to apply them in a batch.
- *Link to a title* compares the boleto with each candidate (CNPJ,
  amount, due date and document number) and links one title or several
  installments of the same vendor whose sum is the amount of the boleto.
- *Undo* reverts the last action while the boleto is not in a payment
  order already exported.
- Add the linked boletos to the payment order; the payment line carries
  the digitable line, the bar code and the interest, fine and discount.
  The title is settled by the return of the payment file or by the bank
  statement, never by the DDA event *paid*.
- *Invoicing > Vendors > Import DDA file* reads a return file with a DDA
  structure.

Known issues / Roadmap
======================

- Alerts of the beneficiary different from the issuer of the NF-e (needs
  fiscal data).
- Allocation of several boletos to one title (1:N).
- A boleto that settles several installments goes as one payment line,
  on the first installment: the others are settled by the return or the
  statement.
