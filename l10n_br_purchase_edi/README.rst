Link between the import of fiscal documents (``l10n_br_fiscal_edi``) and
purchases (``l10n_br_purchase``). It installs itself when both are
present, and it does not depend on the type of the document that was
imported.

An imported vendor document has to answer where it came from before it
becomes a bill. This module keeps the answer on each line of the
document: the purchase order line it corresponds to, and whether that
origin is pending, suggested, resolved, or decided to be without an
order. The bill then links each line to its order line, and the order
counts what was invoiced.

It also adds a screen that puts the lines of the document next to the
open order lines and the quotations of the same supplier, to match them,
create the order that was missing, or record that there is none.

Usage
=====

After importing a vendor NF-e, the lines of the document show an origin
column.

- When the supplier declared the order and the item in the file and
  exactly one open order line has the product, the origin is resolved by
  itself.
- When the supplier has a single open order line for the product, the
  origin is suggested. Press **Confirm Origins** on the document to
  accept the suggestions.
- When there are several candidates, the origin stays pending and the
  line form lets you choose the order line.

**Generate Invoice** refuses the document while a line has a suggested
origin or a pending one with candidates. The bill links each line to its
order line, fills the source document with the order number, and the
order shows the invoiced quantity.

**Match with Orders** opens the reconciliation of the document: its
lines, the confirmed order lines with their balance and the quotations
of the supplier. Select the document lines and one order line and press
**Match**. Other buttons:

- **Undo**: the origin goes back to pending.
- **Without Order**: records that there is no order, with who did it and
  when.
- **Open Quotation**: opens the quotation so the buyer confirms it. A
  quotation cannot be matched; once the order is confirmed the line
  receives the suggestion.
- **Create Order from the Document**: creates a draft purchase order
  with the selected lines (supplier, product, quantity and price of the
  document). It is not confirmed; when the buyer confirms it, the line
  receives the suggestion.

Known issues / Roadmap
======================

- Receipts (stock) and purchase requests as sources of the
  reconciliation: each module adds its ``SELECT`` to ``_match_sources``
  of ``l10n_br_purchase_edi.match``, with the next source type of the
  ids.
- A separate strip of weaker candidates (same product, supplier
  different or not defined) for purchases made outside the system.
- A menu with the pending documents grouped by supplier.
- The tolerance of the ordered quantity (``_import_quantity_tolerance``)
  is zero here; the stock link may extend it.
- A bill that already exists is not changed when the origin is decided
  later.
